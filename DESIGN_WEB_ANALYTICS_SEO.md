## 0. Decisions evaluated and dropped

Recorded the way M17 records dropping Prometheus and M1 records declining the
FMP API — deliberate "no"s, not oversights.

- **Google Analytics 4 — dropped.** Sets cookies → triggers a consent-banner
  obligation on a public site, ships heavy third-party JS, and hands visitor
  data to Google. All cost, no benefit for a personal screener.
- **Umami — dropped.** Nicer dashboards than GoatCounter but requires a
  Postgres (or MySQL) instance alongside the app container. At this site's
  traffic that second stateful service is pure operational overhead. GoatCounter
  is a single Go binary + one sqlite file.
- **Cloud Run request logs as the *sole* metric — dropped as primary, kept as a
  free cross-check.** Cloud Monitoring already exposes `request_count` for the
  `report-web` service at zero cost and zero client JS, but it can't give unique
  visitors, referrers, or per-page breakdown, and it counts bot/health-check
  traffic. It stays as a sanity signal (§2.6), not the product.

**What we build:** cookieless self-hosted GoatCounter for real visitor
analytics (§2), plus generated `robots.txt` + `sitemap.xml` + per-page SEO meta
(§3), both wired through the existing config-gating pattern so **dev stays
un-indexed and uncounted**.

## 1. Inherited constraints (non-negotiable)

1. **Static-site + generated-artifact model.** `report.py` emits static HTML;
   nginx serves `REPORT_DIR`. Any file the browser must reach — `robots.txt`,
   `sitemap.xml`, an `og-image` — **must be written into `REPORT_DIR`**, exactly
   like the archive CSVs (`report.py:1368`, "must live under REPORT_DIR"). It
   cannot be baked into the `report-web` nginx image, because on prod the GCS
   FUSE volume mounts *over* the image's web root (`nginx.conf` `root
   /mnt/data/report`); anything baked in is shadowed by the mount.

2. **HTML is generated by the *Job*, not the web service.** The daily-screen
   Cloud Run **Job** runs `report.py`, bakes all `<head>` content, and writes to
   the bucket; the `report-web` **Service** only serves bytes. Therefore every
   new env var below (`MUNGER_SITE_URL`, `MUNGER_ANALYTICS_URL`) is set on the
   **Job**, alongside `MUNGER_GRAFANA_URL` — never on the service. This also
   means a config change only takes effect on the **next generation**, not
   immediately (acceptable: the site regenerates daily).

3. **Config-gated feature pattern.** Optional, deployment-specific output is
   gated on an env-derived constant that defaults to empty — `GRAFANA_BASE_URL`
   (`config.py:189`, `MUNGER_GRAFANA_URL`) is the template. New URL-dependent
   output follows the same shape: **absent constant → dev behavior** (no
   absolute URLs, `noindex`, no analytics). This is what keeps k3s-dev and
   local runs out of search indexes and out of prod's visitor counts for free.

4. **Two-environment reality.** `gramunger.com` is prod (Cloud Run); k3s is dev
   (and DHCP-IP-drift-prone — see the pi-k3s memory). Only prod is indexed and
   counted. Enforced by constraint 3, not by hand.

5. **No secrets involved.** Unlike the P&L/Alpaca boundary (M14/M16), nothing
   here touches credentials. The only privacy surface is *visitor* data, which
   the self-hosted-cookieless choice keeps entirely first-party.

## 2. Metrics: self-hosted GoatCounter

### 2.1 Why GoatCounter fits

- **Cookieless.** Counts a unique visit by hashing `IP + User-Agent + a daily
  rotating salt`; the salt is discarded each day, so nothing durable identifies
  a person. No cookie ⇒ **no ePrivacy consent-banner requirement** — that
  legal trigger is specifically about storing/reading data on the visitor's
  device, which this doesn't do, and is the single biggest reason to avoid
  GA4 here. **Precision (staff-engineer-reviewer, retroactive review,
  2026-07-30):** this is not the same claim as "no GDPR obligations at all" —
  a same-day-salted hash of an IP is pseudonymization, not anonymization
  (IPv4 space is small enough to be brute-forceable within the day), so the
  underlying data is still personal data under GDPR. That's a well-accepted
  "legitimate interest" basis for first-party audience measurement (no
  cross-site tracking, no persistent identifier, short retention), not a
  blocker, but it means a one-line privacy notice and a confirmed data-
  retention setting in GoatCounter are the honest completion of this claim,
  not "no obligations."
- **One container, one file.** A single Go binary with an embedded sqlite DB.
  Backup = copy one file.
- **~3 KB async snippet**, loaded from our own domain — no third-party origin,
  so it survives ad-blockers far better than GA and leaks nothing cross-site.

### 2.2 Where it runs

**Recommendation: Unraid Docker** (`192.168.1.36`, the always-on media-stack
host), not k3s. k3s is the dev cluster and is subject to IP drift; analytics is
a persistent always-on service and belongs on the stable always-on box next to
the other Docker services.

- Container: `arp242/goatcounter` (or build from source), one published port
  behind the existing reverse proxy.
- Data: sqlite file on the Unraid array (`/mnt/user/appdata/goatcounter/`), so
  it's inside the existing appdata backup scope.
- Public hostname: as-built, **`count.gramunger.com`**, not the `stats.`
  originally proposed here — `stats.` and `analytics.` both turned out to be
  silently unpublishable in this Cloudflare zone (API accepts the record,
  authoritative NS returns NXDOMAIN; likely leftover Zero-Trust/Access or SaaS
  custom-hostnames), found live during M18.1. Fronted by the box's own Caddy
  (not the media-stack's shared reverse proxy), TLS via an LE `*.gramunger.com`
  wildcard origin cert. GoatCounter's site is registered for the
  `count.gramunger.com` code so it accepts our count beacons.

### 2.3 How the snippet reaches the pages

A new gated constant and one shared `<head>` fragment, mirroring
`_FAVICON_LINK`:

```python
# config.py — alongside GRAFANA_BASE_URL
ANALYTICS_URL = os.environ.get("MUNGER_ANALYTICS_URL", "")  # e.g. https://count.gramunger.com/count
```

```python
# report.py — alongside _FAVICON_LINK
_ANALYTICS_SNIPPET = (
    f'<script data-goatcounter="{html.escape(config.ANALYTICS_URL, quote=True)}" '
    f'async src="//{host_of(config.ANALYTICS_URL)}/count.js"></script>'
) if config.ANALYTICS_URL else ""
```

Every page's `<head>` gains `{_ANALYTICS_SNIPPET}` next to `{_FAVICON_LINK}`.
When `MUNGER_ANALYTICS_URL` is unset (all dev/local runs) the fragment is the
empty string → **dev traffic is never reported to prod stats**. Set the env var
only on the prod daily-screen Job (constraint 2).

### 2.4 What we get to see

The GoatCounter dashboard at `count.gramunger.com` gives: total + unique
visits, per-page breakdown (`index` vs `tickers` vs `pnl` vs `dashboards`),
referrers, top browsers/OS/countries, and a visits-over-time chart — the "number
of visitors" the request asked for, plus the context that makes it useful.

### 2.5 SPA/multi-page note

The site is genuinely multi-page (separate `.html` files, full navigations), so
the default page-load beacon counts every page correctly — no
`count({path})`-on-route-change wiring needed (that's only for SPAs).

### 2.6 Free cross-check (kept, not built)

Cloud Monitoring's `run.googleapis.com/request_count` for the `report-web`
service is already emitted. It over-counts (bots, the GCS-mount health path) but
is a zero-effort sanity check that GoatCounter's numbers are in the right
ballpark. No work item — just a note for whoever wonders why the two disagree.

## 3. robots.txt + SEO

### 3.1 New config constant driving all absolute URLs

```python
# config.py
SITE_BASE_URL = os.environ.get("MUNGER_SITE_URL", "").rstrip("/")  # e.g. https://gramunger.com
```

This one constant gates everything that needs an absolute origin: canonical
links, Open Graph URLs, the sitemap, and the "index me" vs "don't" decision.
**Unset (dev) ⇒ noindex, no sitemap, no absolute URLs.** Set it on the prod Job.

### 3.2 robots.txt (generated into REPORT_DIR)

Written by `generate_report()` via the existing `_write_text_atomically`, for
the reason in constraint 1 (must be at the served web root).

- **Prod** (`SITE_BASE_URL` set):

  ```
  User-agent: *
  Allow: /
  Disallow: /progress.json
  Disallow: /screen_results_archive/
  Sitemap: https://gramunger.com/sitemap.xml
  ```

  `progress.json` (the live-run poll file, `config.py:179`) and the raw archive
  CSVs are operational artifacts, not content — kept out of the index without
  blocking the real pages. `tickers.html` is heavy (~760 KB) but is legitimate
  content and stays crawlable.

- **Dev** (`SITE_BASE_URL` unset): `User-agent: *` / `Disallow: /` — belt-and-
  suspenders so a dev deploy that somehow becomes reachable never gets indexed.

### 3.3 Per-page SEO `<head>`

A shared helper replaces the hand-written `<meta charset><title>` opener on
each page:

```python
def _seo_head(title: str, description: str, path: str) -> str:
    # path e.g. "index.html"; canonical/OG only when SITE_BASE_URL is set.
```

emitting, per page:

| Tag | Value | Notes |
|---|---|---|
| `<meta name="viewport">` | `width=device-width, initial-scale=1` | **Currently missing on every page** — mobile + SEO win, biggest single gap. |
| `<html lang="en">` | | Currently no `lang`. |
| `<meta name="description">` | page-specific, ≤155 chars | e.g. index: "Daily quality-value stock screen — current candidate picks with the metrics behind each score." |
| `<link rel="canonical">` | `{SITE_BASE_URL}/{path}` | Gated; omitted on dev. |
| `<meta name="robots">` | `index,follow` prod / `noindex,nofollow` dev | Driven by `SITE_BASE_URL`. |
| Open Graph | `og:title`, `og:description`, `og:url`, `og:type=website`, `og:site_name=Munger Screener`, `og:image` | For link unfurls (Slack/iMessage/etc.). Gated on `SITE_BASE_URL`. |
| Twitter card | `twitter:card=summary_large_image` + title/description/image | |

**og:image** — needs one static social-preview asset (1200×630). Cheapest path:
generate a simple SVG→PNG card once (title + the favicon glyph on the site's
gradient) and write it to `REPORT_DIR/og-image.png`; open question 5.4 flags
the "who produces it" decision. Until it exists, omit `og:image` rather than
point at a 404.

### 3.4 sitemap.xml (generated, gated)

When `SITE_BASE_URL` is set, `generate_report()` writes `sitemap.xml` listing
the canonical pages actually generated this run — `index.html`, `tickers.html`,
`pnl.html`, and **either** `dashboards.html` **or** `calendar.html` (the
`GRAFANA_BASE_URL` fork at `report.py:1496`), each with `<lastmod>` = the
generation date. Skip `progress.json` and archive CSVs (match robots). Unset ⇒
no sitemap written.

### 3.5 Structured data / JSON-LD — deliberately minimal

A single `WebSite` JSON-LD block is fine and low-risk. **Do not** add
`FinancialProduct`/`InvestmentOrDeposit` or any rating/advice schema — this is a
paper-trading screener, and advice-shaped structured data would misrepresent it
and invite the wrong search treatment. (Whether the pages need a visible
"not investment advice" disclaimer is a separate content decision, out of scope
for M18 — flagged, not built.)

### 3.6 Google Search Console

To read Google's own crawl/index view, verify ownership once — preferably by a
**DNS TXT record** on `gramunger.com` (survives redeploys; no page change),
rather than the HTML-meta method (which would need another gated tag). Then
submit `sitemap.xml`. One-time manual step, noted in the rollout.

| `MUNGER_SITE_URL` | `SITE_BASE_URL` | `https://gramunger.com` | unset → noindex |

GoatCounter container + `stats.` DNS/proxy (§2.2).

## 5. Testing & verification

- **Unit (pytest, existing `tests/`):**
  - `robots.txt` + `sitemap.xml` are written when `SITE_BASE_URL` is set, and
    the sitemap lists exactly the pages generated (respecting the
    dashboards/calendar fork).
  - Neither is written, and every page carries `noindex`, when `SITE_BASE_URL`
    is unset.
  - The analytics `<script>` appears in `<head>` iff `ANALYTICS_URL` is set.
  - Every page has `viewport` + a non-empty `description`.
- **Manual, post-deploy:** `curl https://gramunger.com/robots.txt` and
  `/sitemap.xml`; validate OG via a Slack/iMessage unfurl; register the site in
  GoatCounter and confirm a real hit lands; submit the sitemap in Search
  Console.
